# AI 播客知识采集系统 — 需求文档 v1.0

## 用户故事

> 作为一个关注 AI 领域的投资人/创业者，我希望用最少的时间，系统性地从播客中获取高质量信息，沉淀到我的知识库中。

## 用户画像

- 关注 AI 创业实战、技术前沿、投资视角三个方向
- **最核心偏好：优秀企业家/行业人物的深度访谈**
- 中英文播客都关注
- 痛点：信息源分散、好内容遗漏、听完无沉淀

## 核心矛盾

**时间有限 vs 信息过载**——不是要听更多，而是要用更少时间获取更多价值。

## 系统闭环

```
发现（维护订阅源）→ 评分（5 维度打分）→ 推荐（每日日报）→ 归档（9+ 分自动入库）
```

### 第一层：发现
- 维护 AI 播客订阅清单（`.infra/podcasts/feeds.yaml`）
- 中英文各 8-10 个播客源
- 每日定时扫描最新单集

### 第二层：评分
- 5 维度加权评分：嘉宾分量(30%) + 相关度(25%) + 信息密度(20%) + 时效性(15%) + 形式加分(10%)
- 嘉宾分量权重最高，体现用户偏好
- 评分标准见 `.infra/podcasts/scoring-guide.md`

### 第三层：推荐
- 每日生成播客日报（`notes/podcasts/YYYY-MM-DD-播客日报.md`）
- 7+ 分推荐，含摘要和要点预览
- 用户随时可手动触发扫描

### 第四层：归档
- 9+ 分自动搜索文字版并归档到 `knowledge/`
- 搜不到文字版则标记 `transcript: false`，仅存摘要
- 归档后自动更新 index.md 和建立双链

## 已确认的决策

- [x] 筛选频率：每天定时 + 随时可问
- [x] 播客来源：中英文都要
- [x] 人脉图谱：MVP 不做，后续迭代
- [x] Plaud 整合：MVP 不做，后续迭代
- [x] 自动化程度：定时 + 手动双模式
- [x] 全文问题：搜索为主，搜不到就标记跳过

## 文件架构

```
.infra/podcasts/
├── feeds.yaml          # 订阅清单
├── episodes.yaml       # 已扫描单集记录
└── scoring-guide.md    # 评分标准

.infra/templates/
└── podcast-template.md # 播客笔记模板

notes/podcasts/
└── YYYY-MM-DD-播客日报.md  # 每日推荐（运行时生成）

knowledge/tech/ 或 business/
└── YYYY-MM-DD-标题.md      # 9+ 分归档笔记（运行时生成）
```
