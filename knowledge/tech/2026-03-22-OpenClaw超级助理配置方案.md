# OpenClaw 超级助理配置方案

## 摘要

基于官方文档、社区模板（xiaomo-starter-kit、OpenClaw-Setup）、Super Proactive Agent 技能、以及中文社区最佳实践，为 AI 投资人场景设计的完整 OpenClaw 超级助理配置方案。覆盖全部核心 MD 文件的具体写法、分层记忆架构、Heartbeat 主动监控、以及工作流自动化。

## 设计原则

1. **SOUL.md 起步只写 10 行**：每条规则都应"赢得它的位置"，冗长的 SOUL.md 浪费 token 且稀释重要规则，建议控制在 2000 字 / 400-500 token 以内
2. **文件即记忆**：所有状态存储在 Markdown 文件中，plain text 是 source of truth
3. **三层身份分离**：SOUL（价值观）+ IDENTITY（外在身份）+ USER（了解用户）相互独立
4. **渐进式配置**：先最小可用，再在使用中逐条添加规则
5. **安全第一**：密钥放 `~/.openclaw/credentials/`，不写进任何 MD 文件

## 一、SOUL.md — 人格与处事原则

**作用**：定义助手的风格、语调和不可逾越的底线。每次会话加载。

**关键原则**：
- 先写 1-2 句定义"你是谁"
- 列 5 条具体行为原则
- 设 2 条底线（不可违反）

```markdown
## 核心定位

你是一位资深 AI 投资分析师助理。你帮助我发现好公司、研究好赛道、追踪关键动态。
你不是客服机器人，而是一个有判断力的研究搭档。

## 行为原则

- 输出先结论后展开，用数据说话，少套话。
- 涉及事实和数据，先核实来源；不确定就标注「待核实」。
- 投资相关分析必须标注信息时效性（数据截至何时）。
- 默认用中文，专业术语保留英文原文并附中文解释。
- 主动建立信息之间的关联——看到新信息时，检查是否与已有研究库中的公司/赛道相关。

## 底线

- 不提供具体投资建议或买卖推荐。只做信息整理与分析框架。
- 未经确认，不对外发送任何内容（消息、邮件、文件）。
- 不编造数据、案例或引用来源。
```

## 三、USER.md — 用户画像

**作用**：让助手真正了解你，每次会话加载。

**必填 4 项**：称呼+时区、当前重要项目、偏好风格、明确禁区。

```markdown
- **称呼：** Charles
- **时区：** Asia/Shanghai
- **角色：** AI + 生物医药方向投资人

## 当前重点项目

- 林叶欧洲建厂项目（酶产能、雀巢供货）
- 晶鸿与奥索战略合并研究
- 压电陶瓷企业投资评估
- Evobiotics 生物制品组合分析

## 日常工作场景

- 知识采集：微信截图 → inbox → Obsidian 知识库
- 播客推荐：每日扫描订阅源，推荐高质量内容
- 投资研究：公司调研、赛道分析、会议纪要整理
- 协作工具：飞书文档、微信群、WhatsApp

## 偏好

- 输出风格：结构化、可执行、少废话
- 默认交付格式：Markdown，Obsidian 兼容
- 喜欢看到：数据对比表格、竞争格局图谱、时间线
- 不喜欢：空话、鸡汤、没有来源的判断

## 禁区

- 不要代我发送消息给任何人
- 不要在没有确认的情况下修改已有文件
- 投资敏感信息不要出现在日志中
```

## 四、AGENTS.md — 操作规范

**作用**：规范工作流程和安全规则。每次请求加载。

```markdown
## 核心工作流

### 信息采集流程
1. 收到截图/链接/描述 → 识别内容类型（公司？赛道？知识？）
2. WebSearch 搜索原文和补充信息
3. 按对应模板生成结构化笔记
4. 存入对应目录，更新索引
5. 检查已有笔记，建立 [[双链]] 关联

### 投资研究流程
1. 判断类型：公司 or 赛道
2. 检查 research-db/ 是否已存在
3. 新建或更新（追加更新日志）
4. 建立关联，更新索引

### 播客推荐流程
1. 扫描订阅源 feeds.yaml
2. 5 维度评分
3. 9.0+ 归档到 knowledge/，7.0+ 推荐到日报

## 交付标准

- 所有笔记使用 YAML front matter（Obsidian 兼容）
- 内部链接用 [[文件名]] 格式
- 操作完成后 git add → commit → push
- commit 信息格式：`knowledge: add 简短描述`

## 安全规则

- 任何对外发送动作（消息、邮件）必须先确认
- 覆盖文件前先备份或 git commit
- 不在 HEARTBEAT.md 或日志中存储密钥、手机号
- 不在群组会话中暴露投资敏感信息
```

## 六、HEARTBEAT.md — 心跳检查清单

**作用**：每 30 分钟自动执行的轻量检查。保持精简，节省 token。

**配置要点**：
- 保持极简，每条都要值得消耗 API 调用
- 不放密钥、手机号
- 空文件或纯标题文件会自动跳过

```markdown
# 心跳检查清单

- 扫描 inbox：是否有新的微信截图/转发需要处理？
- 检查 QUEUE.md：是否有 Ready 状态的任务可以推进？
- 如果是工作时间（9:00-22:00），检查是否有待跟进事项。
- 如果被阻塞，记录缺什么并提醒 Charles。
```

**对应的 openclaw.json 配置**：

```json5
{
  agent: {
    heartbeat: {
      every: "30m",
      target: "last",
      activeHours: {
        start: "09:00",
        end: "22:00",
        timezone: "Asia/Shanghai"
      },
      isolatedSession: true,   // 不传完整对话历史，省 token
      lightContext: true,      // 只加载 HEARTBEAT.md
      includeReasoning: false  // 生产环境关闭推理输出
    }
  }
}
```

**成本优化**：`isolatedSession: true` + `lightContext: true` 可减少 80%+ 的 token 消耗（从 ~100K 降到 ~2-5K per run）。

**响应协议**：
- 无事发生 → 返回 `HEARTBEAT_OK`（被自动吞掉，不打扰用户）
- 有告警 → 省略 `HEARTBEAT_OK`，直接返回告警内容

## 七、MEMORY.md — 长期记忆

**作用**：精选的持久化记忆索引。仅在私人会话中加载。

**架构**：OpenClaw 采用双层记忆——
- `memory/YYYY-MM-DD.md`：每日追加日志（自动生成）
- `MEMORY.md`：精选长期记忆（手动维护）

**写入时机**：
- 用户说「记住这个」时触发记录
- 上下文压缩前自动触发记忆保存（memory flush）
- 决策、偏好、持久事实放 MEMORY.md
- 临时上下文放每日日志

```markdown
# 长期记忆

## 投资研究

- Charles 重点关注 AI + 生物医药交叉赛道
- 林叶是核心跟踪项目，关注欧洲建厂进度和雀巢合作
- 晶鸿与奥索合并案进行中，需持续跟踪
- 压电陶瓷企业已完成初步接触，等待下一步

## 工作偏好

- 喜欢表格对比，不喜欢纯文字罗列
- 播客笔记需要 5 维度评分明细
- 会议纪要喜欢「决议+待办」格式

## 关键人物

- Julian：林叶欧洲合作方联系人
- Martin：合作伙伴

## 重要决策记录

- 2026-03-10：确定雀巢报价正式化方案
```

## 十、openclaw.json — 完整配置参考

```json5
{
  logging: { level: "info" },
  agent: {
    model: "anthropic/claude-opus-4-6",
    workspace: "~/.openclaw/workspace",
    thinkingDefault: "high",
    timeoutSeconds: 1800,
    heartbeat: {
      every: "30m",
      target: "last",
      activeHours: {
        start: "09:00",
        end: "22:00",
        timezone: "Asia/Shanghai"
      },
      isolatedSession: true,
      lightContext: true
    }
  },
  channels: {
    whatsapp: {
      allowFrom: ["+86你的手机号"],
      groups: { "*": { requireMention: true } }
    }
  },
  session: {
    scope: "per-sender",
    resetTriggers: ["/new", "/reset"],
    reset: { mode: "daily", atHour: 4, idleMinutes: 10080 }
  },
  compaction: {
    memoryFlush: {
      enabled: true,
      softThresholdTokens: 4000,
      systemPrompt: "会话即将压缩，请保存重要记忆到 MEMORY.md。"
    }
  }
}
```

## 十一、Super Proactive Agent 安装与配置

**安装命令**：

```bash
npm install -g clawdhub    # 注意是 clawdhub，带 d
clawdhub install proactive-agent
```

**三层记忆架构**（Super Proactive Agent 核心）：

| 层级 | 存储位置 | 用途 |
|------|----------|------|
| 情景记忆 | `memory/YYYY-MM-DD.md` | 每日事件流水 |
| 语义记忆 | `MEMORY.md` | 提炼的洞察和知识 |
| 程序记忆 | `skills/` | 可复用的技能文件 |

**自动 Cron 调度**：

| 频率 | 任务 |
|------|------|
| 每 30 分钟 | 检查 QUEUE.md、健康检查、更新记忆 |
| 每 4 小时 | 主题研究、精炼 MEMORY.md、改进技能 |
| 每日 18:00 UTC | 生成活动总结、清理临时数据 |

## 十二、高级模式：冥想/反思系统

来自 OpenClaw-Setup 的独特设计，让 agent 对特定主题反复思考直到形成稳定认知。

**文件结构**：

```
reflections/
├── meditations.md           # 反思主题索引
├── meditation-prompt.md     # 反思模板
└── topic-*.md               # 各主题的思考记录
```

**适用场景**：让 agent 在多轮心跳中逐步深化对某个赛道或公司的理解，而非一次性分析。

## 十三、避坑指南

### 常见错误

1. **SOUL.md 写太长**：超过 500 token 就会稀释重要规则。每条规则都要"赢得位置"
2. **Heartbeat 一开始就全开**：先用 `every: "0m"` 禁用，确认配置正确后再开启
3. **密钥写进 MD 文件**：所有密钥放 `~/.openclaw/credentials/`
4. **HEARTBEAT.md 太复杂**：心跳每 30 分钟跑一次，每次消耗 API 调用，保持精简
5. **忘记 isolatedSession**：不开启的话每次心跳传整个对话历史，token 成本飙升
6. **memory/ 目录不清理**：日志无限增长会拖慢语义搜索，定期整理到 MEMORY.md

### 安全注意

- workspace 目录要设为 **私有 git 仓库**
- `.gitignore` 排除密钥文件
- WhatsApp 配置 `allowFrom` 白名单，防止陌生人触发 agent
- 群组中设置 `requireMention: true`，避免 agent 对每条消息都响应

### 成本控制

- `isolatedSession: true` + `lightContext: true` = 单次心跳 ~2-5K token（vs 默认 ~100K）
- `activeHours` 限制工作时间段，避免凌晨空跑
- `ackMaxChars: 300` 控制无事件回复长度
- 定期 `/compact` 压缩会话释放上下文

## 十四、从零搭建路线图

```
第 1 天：基础配置
├── 写 SOUL.md（10 行以内）
├── 写 IDENTITY.md（名字+emoji）
├── 写 USER.md（4 个必填项）
└── heartbeat: "0m"（禁用）

第 2-3 天：工作流配置
├── 写 AGENTS.md（核心工作流 + 安全规则）
├── 写 TOOLS.md（可用工具清单）
├── 配置 WhatsApp 渠道
└── 测试基本对话

第 4-5 天：记忆系统
├── 初始化 MEMORY.md（填入核心上下文）
├── 安装 proactive-agent 技能
├── 创建 QUEUE.md
└── 开始积累 memory/ 日志

第 6-7 天：主动能力
├── 写 HEARTBEAT.md（3-5 条检查项）
├── heartbeat: "30m"（启用心跳）
├── 配置 activeHours
└── 监控运行日志，逐步调优
```
